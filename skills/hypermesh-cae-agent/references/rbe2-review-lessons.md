# RBE2 审核与创建经验

## 识别规则

- 只扫描当前可见 HyperMesh 模型的 shell 圆形自由边；扫描是只读的。
- 先拟合每个闭合自由边的圆心、半径、法向和拟合残差。
- 默认圆心配对容差为 5 mm；优先展示两个圆心距离不超过容差的成对候选。
- 候选顺序固定为 `paired_circles`、`ambiguous_pair`、`single_circle`。
- 一个圆边若同时接近多个圆边，必须标记为歧义候选，不能自动判断连接对象。
- 拟合退化、共线或无法形成圆的自由边要跳过并记录原因，不能使整个扫描失败。
- 重复扫描前必须清空 Tcl 临时数组：
  `mcp_circular_edge_count`、`mcp_circular_edge_nodes`、
  `mcp_circular_element_component`、`mcp_circular_adjacency`、
  `mcp_circular_visited`。

## 审核与显示

- RBE2 仅在工程师逐条确认后才允许创建；扫描或打开面板绝不创建连接。
- Next/Previous 时恢复显示、遮罩无关实体，只显示候选关联的 component/网格，并将视角放到圆心节点附近。
- 面板必须置顶，支持确认、排除和人工补加成对圆孔。
- 长时间自由边扫描使用 GUI 异步任务，避免占用单个同步 socket 导致 listener 断开。

## 创建规则

- 连接创建核心使用统一面板内嵌且带 SHA-256 注释校验的
  `Create_rbe2_to_shell` 宏；不得引入第二个 Tcl 面板或外部 `.tbc` source。
- 创建前先保存恢复模型；创建过程中保留工程师选择的节点标记。
- 每个候选创建后记录创建出的 RBE2 单元号；单个候选失败应记录失败原因并继续后续候选。
  若宏报错后仍生成了新的 RBE2，则以实际新增单元为准记录为成功，避免重试重复创建；
  成功候选标记为 `applied`，重试时只允许继续失败候选。
- RBE2 审计过程位于自定义 Tcl namespace 时，Tcl 内置文件命令必须使用全局限定：
  `::open` 和 `::close`。否则会分别误调用面板的 `open`/`close` 过程。
- 审计 JSON 数组应先构造字符串再转义方括号，例如：
  `set created_id_json [join $new_rbe2_ids ,]`，再写入 `\[$created_id_json\]`；
  不要在双层 `[...]` 中直接嵌套 `join`，否则单元号会被当作 Tcl 命令执行。

## 文件与恢复策略

- 任何会改变模型的操作都先另存为恢复文件；原始模型不覆盖。
- 输出文件使用日期、时间和操作命名，例如：
  `door_20260731_131409_rbe2_review.hm`。
- 同一大步骤内部使用一个最终输出文件，配套保留执行 Tcl、运行日志、审计日志和 manifest；不要每个小动作都生成一个新模型。
- 建议的阶段命名：
  `输入模型_日期时间_操作.hm`、
  `输入模型_日期时间_操作.tcl`、
  `输入模型_日期时间_操作.audit.jsonl`。
- 只有在最终模型、审计和报告验证成功后，才删除该大步骤的中间恢复文件；原始输入和最终输出不得自动删除。
- 删除前应在 manifest 中记录被删除文件清单，并保留最终恢复点或由工程师明确批准清理。
