# 车门 HyperMesh Agent 端到端协同流程（HM17，当前已验证 Profile）

> 这是 HyperMesh CAE Agent 当前已验证的车门参考实现，不是对所有零部件、行业标准或 CAD 语义的通用承诺。通用平台能力与其他 Profile 的扩展边界见包根目录 `README.md` 和 `ARCHITECTURE.md`。

## 目的

将车门 CAD 到 CAE 前处理固化为一个可迁移的七阶段协作合同。任何接入本整合包的 agent 都必须按阶段、权限和交接条件工作；不得把“自动化”理解为绕过工程师的几何、包边、网格质量或连接工程判断。

本流程适用于 HyperMesh 17 车门模型。模型专属的网格尺寸、质量阈值、材料厚度、连接规则和求解器模板仍须由工程师给出或从已审计模型中读回。

## 启动条件

1. 工程师打开目标 HyperMesh 模型并连接 MCP。
2. agent 记录输入模型、求解器模板、输出目录、当前阶段和工程师提供的标准。
3. agent 先将当前输入另存为带日期、阶段和操作名的本大步骤工作模型，再创建 run 目录和待执行 Tcl 目录；原始输入模型不得被覆盖。
4. agent 只能在前一阶段已经验收或工程师明确放行后，进入下一阶段。

所有阶段使用以下状态：not_started、agent_running、engineer_action_required、engineer_decision_required、blocked、accepted。agent 不得自行把 engineer_action_required 或 engineer_decision_required 改为 accepted。

## 阶段总表

| 阶段 | 主责 | agent 权限 | 工程师交接点 | 阶段出口 |
| --- | --- | --- | --- | --- |
| 1. 模型管理与组织 | agent | 完全执行 | 提供命名/分类特殊约束 | 组件、颜色、层级与模型清单已审计 |
| 2. 中面抽取 | agent | 完全执行 | 仅处理无法判定厚度或层数的例外 | 每个来源与中面的映射、厚度证据已记录 |
| 3. 几何清理 | 工程师主导 | 运行低风险 Auto Cleanup、汇总问题 | 决定细节清理策略并验收 | 几何满足后续网格前提 |
| 4. 包边处理 | 工程师主导 | 不介入包边建模和拓扑修复 | 完成包边几何和网格后交回 | baobian/相关接口边界已明确并验收 |
| 5. 网格划分 | agent | 完全执行 | 提供参数与例外批准 | 每个批准组件的 2D 网格、报告和恢复模型齐全 |
| 6. 网格检查与修复 | 工程师主导 | 检查、定位、生成候选；仅执行明确指令的局部修复 | 判断质量、连通性、局部细节和修复方法 | 工程师接受网格或给出未解决项 |
| 7. 创建 connectors | 工程师判断、agent 执行 | 扫描、展示、记录和按批准创建 | 审核点焊、胶粘、RBE2 候选并确认提交 | 连接审计、P07 另存为结果模型与清理清单齐全 |

当前汇报中的效益估计仅作目标：前五阶段的可重复劳动预计可减少约 50%，连接扫描与审核工作流可减少约 80% 的重复操作时间。该数字不是模型质量或交付承诺，应在项目实际运行中测量。

## 1. 模型管理与组织（全 agent）

### 输入

- CAD/已有 HM 模型；
- 工程师给出的车型、部件命名、颜色或导出要求；没有特殊约束时使用整合包的功能化命名和配色规则。

### agent 操作

1. 导入或读取模型，建立组件、collector、几何实体、单元和连接器的初始清单。
2. 识别重复、参考、主体、内板、外板、窗框/玻璃、紧固件、焊点和胶粘等功能类别；不凭颜色猜测永久语义。
3. 对组件执行统一命名与功能配色，保留原始 ID、实体归属、属性和连接器。
4. 清点点焊和胶粘参考几何；对用途明确的对象分别归集到 `connector_ref_spot_weld` 和 `connector_ref_glue`，保留原 component 映射。不得移动板件网格、结构件或已实现 connector；语义不明的对象列为人工归类项。
5. 输出模型组织清单、组件名称映射、颜色映射、连接参考 component 映射和导入/导出日志。

### 工程师介入与出口

工程师只在名称含义、功能分类或导出目标不明确时补充规则。出口为模型树清晰、可读、可检索，且没有因整理改变几何、网格、属性或连接关系。

## 2. 中面抽取（全 agent）

### 输入

已组织的几何模型以及可获得的实体厚度信息。

### agent 操作

1. 按组件逐一识别尚未网格化的 solids 与 surfaces，防止同一结构重复抽取。
2. 对 solid 依据实际厚度抽取中面；对 surface 先判断是否为单层壳面、双层/多层或仅为参考几何，再决定是否抽取。
3. 建立来源实体、中面组件、厚度证据和异常项的映射；中面组件与来源组件保持可追溯。
4. 发现无法可靠判断层数、厚度或结构关系时停止该组件，列入工程师例外清单，不猜测。

### 工程师介入与出口

默认由 agent 完成。工程师只处理层数/厚度或几何语义不能从模型确定的例外。出口为中面完整、无重复抽取、异常件清单明确，并保留来源映射。

## 3. 几何清理（工程师主导，agent 辅助）

### agent 操作

1. 从本阶段输入另存为工作模型后，执行低风险、可回退的 Auto Cleanup；仅在破坏性子操作前保存阶段内部恢复模型。
2. 扫描小缝隙、重复面、自由边、碎面、短边、孔洞和潜在几何错误，按组件汇总。
3. 只对工程师已批准的简单规则执行清理；复杂拓扑、关键特征和会改变包边/装配关系的清理不自行决定。
4. 输出清理前后数量、执行 Tcl、未处理项和可能影响中面/网格的风险。

### 工程师操作与出口

工程师决定复杂清理的保留、删除、替换、分割或重构方案。出口为工程师确认的可网格化几何和已记录的保留缺陷。

## 4. 包边处理（agent 不介入）

包边处理细节高度依赖 GUI、局部拓扑和工程师经验。agent 不得自动创建、切割、删除、重构或优化包边，也不得以全局 Equivalence 或重划网格替代工程师处理。

工程师完成包边几何和相关网格后，交付以下信息给后续阶段：baobian 是否为参考网格、相邻 neiban/waiban 接口、真实外侧自由边、可修改目标板件、以及已接受的包边网格状态。

## 5. 网格划分（全 agent）

### 输入

工程师批准的中面/包边结果、每个组件的网格参数、质量标准和不允许自动重划的区域。

### agent 操作

1. 对每个组件独立处理；进入 BatchMesh 前从已验收输入另存为本大步骤工作模型并记录参数，阶段内部仅保留必要恢复快照。
2. 首选 BatchMesh 生成 2D 网格；当 BatchMesh 明确失败或不适合时，把 2D mesh/局部 Automesh 作为受控回退，不能陷入重复重试。
3. 对已由工程师处理的 baobian，仅按批准范围读取和连接，不重划或改变其网格。
4. 每个组件结束后读回节点、单元、三角形/四边形、失败信息和保存状态；异常即停止当前组件并报告。
5. 本阶段结束后只保留已验证的阶段模型、Tcl、日志、参数和汇总报告；依照文件生命周期规则清理已确认无用的中间文件。

### 工程师介入与出口

工程师提供参数、标准和例外规则。出口为已批准组件具备可检查的 2D 网格；失败组件和回退原因清楚列出。

## 6. 网格检查与修复（工程师主导，agent 辅助）

### agent 操作

1. 依据工程师提供的质量配置检查连通性、重复单元、孤立节点、自由边、缺网、单元质量、尺寸过渡和几何贴合。
2. 将问题分为连通性、质量、局部细节和网格优化四类，生成组件级问题列表、局部证据和候选修复顺序。
3. 对包边—板件接口遵循专用节点合并指南：只匹配 baobian 强内侧自由边，目标板件贴向 baobian，外侧边、模糊边和大容差自动合并全部排除。
4. 仅在工程师给出明确方法后执行局部 Combine、Split、Smooth、Automesh、Replace 或受控 Equivalence；不自行决定全局修复策略。

### 工程师操作与出口

工程师判断允许项、质量阈值、修复优先级和局部手段，并审核每个高风险修复。出口为工程师接受的网格，或带有位置、原因和风险的未解决项清单。

## 7. 创建 connectors（工程师判断，agent 执行）

### agent 操作

1. 核对点焊参考 component `connector_ref_spot_weld`、胶粘参考 component `connector_ref_glue` 及其实体数量；兼容读取 `cankao`、`hanjie`、`(GL)`、`（GL）`，但不把板件网格当作参考几何归集。
2. 启动统一连接审核插件，扫描点焊、胶粘和圆孔 RBE2 候选。
3. 点焊按参考几何/标记与相邻 FE 组件识别；胶粘同时检查参考区域、相关组件和 shell 网格；RBE2 优先展示中心距离满足容差的圆形自由边对。
4. 按置信度与规则展示候选、局部高亮与放大视图，并允许工程师通过、拒绝或人工补加。
5. 仅把工程师批准的候选提交为 connector；提交前保存阶段内部恢复模型，提交后另存为新的 P07_connectors 结果模型，并读取审计、元素/连接器数量和输出模型。

### 工程师判断与出口

工程师负责判断候选是否真实、是否需要补加、连接类型和最终提交。agent 不得绕过审核创建点焊、胶粘或 RBE2。出口为审核记录、批准列表、连接创建结果和最终模型。

## 阶段交接与异常处理

- 每个阶段只接收上游已 accepted 的模型和工件；出现 Tcl 错误、输出缺失、质量回归或范围不确定时，状态改为 blocked。
- agent 输出工程师接手所需的最小包：当前模型、恢复模型、执行 Tcl、日志、问题列表、局部证据、候选操作和未满足条件。
- 工程师完成手工阶段后，必须明确说明完成范围、允许后续 agent 修改的组件和验收条件。
- 未获得工程师放行时，agent 只能检查、报告或等待，不能跨阶段写模型。
- 每个阶段 accepted 后，agent 先在 run manifest 中记录输入、accepted 输出、`before/checkpoint` 临时模型和删除清单；随后仅清理该阶段内部已经验证的临时文件。原始输入和 accepted 输出不得自动删除。
